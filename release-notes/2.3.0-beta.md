## New Features

- Added v2 renewal preview/commit and operation status endpoints for inspected ARMember Pro 8.1.1 manual recurring subscriptions.
- Renewal reactivates the account, advances exactly one natural billing cycle, and creates one successful payment or explicitly reuses a matching recorded payment.
- Added a dedicated renewal capability and a disabled-by-default setting; renewal also requires activation permission and availability.

## Improvements

- Added state-bound previews, durable operation journaling, payment/cycle uniqueness reservations, idempotent replay, concurrency locks, and conservative reconciliation for uncertain writes.
- Preserved native invoice bookkeeping and suppressed ARMember mailers reached synchronously during renewal.
- Updated API contracts, Postman examples, privacy and retention documentation, and integration tests using supplied native helpers.

## Bug Fixes

- Allow operator-confirmed nonpayment renewal when native suspension clears grace metadata and a later successful payment obscures the earlier failure; retain unrelated restriction guards and report specific rejection reasons.

## Upgrade Notes

- Beta for staging validation; not a production release. Full site lifecycle hooks and integrations still require staging verification.
- Existing v1/v2 routes remain available. Renewal starts disabled and supports Pro 8.1.1 only.
- Review a preview before committing. Preserve the same idempotency key after a timeout. Uncertain operations require reconciliation; never retry them with a new key or payment.
- Renewal journal reservations survive uninstall/reinstall to prevent duplicate settlement.
