## New Features

- Added precise unsupported-subscription rejection reasons (`data.reason`, with `data.field` for malformed schedule fields).

## Improvements

- Explicit nonpayment confirmation is bound to previews, idempotency, and the durable operation journal.
- Added regression tests for cleared grace state, later successful payments, and unrelated restrictions.

## Bug Fixes

- Fixed renewal rejection when native automatic suspension cleared its grace reason and a later success superseded the failed payment. A trusted operator can now provide per-target `suspension_reason: "nonpayment"` after confirming that cause.
- Confirmation requires an overdue target and does not bypass cancellations, administrative restrictions, unrelated grace actions, other-plan restrictions, automatic debit, or invalid/exhausted schedules.

## Upgrade Notes

- Beta for testing; no live renewals or deployment were performed by this change.
- Never default nonpayment confirmation across members. Repeat it unchanged on preview, commit, and replay only for explicitly confirmed targets.
